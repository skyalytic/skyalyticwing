# 任务中心与远程工作区

本文适用于 2.1.1 社区源码。无需 Wing 登录，模型使用你配置的 API 或本地模型。远程主机、容器和第三方渠道的认证仍需分别配置。

## 任务中心

从窗口顶部的“任务中心”进入，查看任务状态、结果、产物、通知、待回答问题与审批。点击任务可返回原对话。

- 中断任务先核对已经生成的文件和外部操作，再选择继续或重试，避免重复执行。
- 自由回答与选项是独立的输入方式；审批继续使用对应的审批入口。
- 主动规则可以按间隔或渠道事件触发，支持仅观察与自动执行。启用前检查目标、权限和模型配置。
- 发送队列展示待发送、失败和待核实的记录。只有确认接收方及实际发送结果后，才应标记已送达；不确定时先核对，避免重复发送。
- 智能体配置支持提示词版本查看、比较与恢复，并可预览当前生效的完整提示词。修改冲突时先重新载入再合并。

定时和主动任务依赖本机进程持续运行、网络及所需模型可用；关闭程序不会使它变成云端常驻服务。

## 远程工作区

在项目面板中选择远程连接，填写连接类型、目标与项目路径：

| 类型   | 目标                               | 前置条件                                        |
| ------ | ---------------------------------- | ----------------------------------------------- |
| SSH    | 主机别名或 `user@host`，可配置端口 | 本机 SSH 客户端可连接；先完成主机身份核验和认证 |
| WSL    | 已安装的发行版名称                 | Windows 上已安装并初始化该 WSL 发行版           |
| Docker | 容器名称或 ID                      | Docker 可用，目标容器正在运行                   |

远程项目路径采用目标环境的绝对 POSIX 路径。先验证连接与目录，再发起文件或终端任务。文件读写、终端和 Git 操作绑定当前远程项目；连接中断会报错，不应自动改为本地执行。浏览器与桌面操作仍作用于本机。

远程子任务支持独立 Git worktree。需要隔离时，目标必须是可用的 Git 仓库，并具备创建工作区所需的权限；共享目录仅适用于明确需要共享的任务。查看子任务结果和变更后再合并，避免多个任务同时修改同一文件。

远程 Office 编辑与画布文件操作经远程工作区读写，保存时检查版本冲突。目标环境缺少运行条件时，应根据错误准备依赖，不要假定每台服务器都已具备全部文档工具。

## 模型协议与执行恢复

模型供应商设置新增 API 协议选择：自动、Chat Completions、Responses。兼容网关应选择其实际支持的协议。Responses 的状态只回传给对应供应商与模型；执行器检查完整工具调用，再执行工具。

长任务包含上下文压缩、检查点与重复执行保护。恢复任务时仍应核实外部操作是否已经完成，检查点不能自动撤销已发送的信息或远端修改。

## 本地验证

先按仓库 README 安装依赖，再运行：

```sh
node scripts/run-backend-tests.cjs --runInBand --testPathPattern='agent-reliability|remote-|scheduler-runtime|account-free'
pnpm --filter @skyalyticwing/frontend test
pnpm version:check
pnpm test:public-source
```

单元测试和模拟端点测试不等于真实 SSH、WSL、Docker、付费模型和消息渠道都已完成实机验收。使用自己的测试项目验证连接、文件保存、取消、断线恢复与子任务隔离后，再执行正式任务。
